 RAYCAST SCRIPT COMMANDS (fresh-machine manual setup -- can't be chezmoi'd):
  - The scripts live in ~/.config/scripts/raycast (chezmoi-deployed, SINGLE source):
    ahk-on, ahk-off, classic-start-menu, glaze-move-right.
    (Old D:\REPOS\scripts\raycast copies were retired -- one source of truth now.)
  - POINT RAYCAST AT THAT DIR by hand: Settings > Extensions > Script Commands >
    Add Directory > C:\Users\senio\.config\scripts\raycast. Raycast stores its script
    directories in a SQLite index (app_index.db), NOT an editable file -> chezmoi
    can't set it for you -- but it's a quick "+"/Add Directory click, not a chore.
    NOTE: that's the SCRIPT COMMANDS setting, NOT "Search Scopes". Search Scopes is for
    finding Applications (.exe/.lnk, e.g. Start Menu); a .ps1 added THERE won't run as a
    command. (Search Scopes scanning both Start Menu dirs is also why dup-installed apps
    like RustDesk/Deskflow/Obsidian show twice -- fixed by removing the duplicate install.)

 WIN+L BRIDGE (move window right) -- a Raycast hotkey, also rebind by hand:
  - Win+L = Raycast captures it -> glaze-move-right.ps1 -> GlazeWM CLI.
  - REQUIRES DisableLockWorkstation=1 (windows-tweaks.reg) else Win+L just locks. Tested.
  - lwin+shift+l = GlazeWM native move-right (bulletproof fallback, always works).
  - Raycast hotkeys live in Raycast's index, not the dotfiles -> re-bind on fresh machine.

------------------------------------------------------------------ GOTCHAS ------
 - find.exe HYDRATES OneDrive: Windows find.exe is a *content* search; scanning
   reads cloud-only files and DOWNLOADS them (fills the disk). FIX: `find` is
   aliased to `fd` (name-only, no content read). Also avoid recursive scans
   (Get-ChildItem -Recurse, lastmod) inside ~/OneDrive. Dehydrate to reclaim:
   attrib +U -P /s /d "D:\OneDrive\*"  (= OneDrive "Free up space", safe/reversible).
 - PowerShell built-in ALIASES shadow functions: cat/ls/ps had to be Remove-Alias'd
   before defining the function. If a unix command "doesn't work," check for a
   built-in alias shadowing it (Get-Command <x> shows the type).
 - bat (`cat`) PAGES long files and looks hung: fixed via ~/.config/bat/config
   (--paging=never) + BAT_CONFIG_PATH env (scoop bat ignores ~/.config otherwise).
   Bare `cat` (no file) waiting on stdin is CORRECT unix behavior (Ctrl+C/Ctrl+D).
 - GlazeWM: opt-in tiling (float by default, allowlist tiles) because of games.
   Core native Windows apps (Snipping Tool, Settings, Notepad...) ARE allowlisted.
 - Identity: "yabo" lives in the prompt + fastfetch; OS account rename happens at
   the factory reset (C:\Users\senio -> C:\Users\yabo). Dotfiles use ~ / $env vars
   so they survive the rename.

--- File Pilot caveat (learned the hard way) ---
- Do NOT enable File Pilot's "set as default file manager" setting. It writes
  HKCU\Software\Classes\Directory\shell\open\command = FPilot.exe "%1", which
  hijacks every "open folder" / "Show in File Explorer". But File Pilot beta is
  single-instance and DISCARDS the %1 path when already running -> every folder
  open just shows its last location (e.g. Screenshots). Symptom: Raycast "Show in
  File Explorer" and path-passing look broken.
- Fix / keep reverted: remove that registry key so real Explorer handles folder
  opening:  reg delete "HKCU\Software\Classes\Directory\shell\open" /f
- Use File Pilot as a manual/standalone browser; let Explorer own "show in folder".
- Also: File Pilot loads Windows shell extensions; MEGAsync's ShellExtX64.dll
  injected into it was a crash source (0xc0000005). Windhawk injection was another.

--- IMAGES: keep the Windows default viewer (do NOT set a custom default) ---
LESSON: making a custom/portable app (IrfanView) the default image handler on
Win11 KILLS File Explorer + File Pilot thumbnails (the custom ProgID has no real
thumbnail provider, and Win11 UserChoiceLatest blocks fixing the association
cleanly). We tried and reverted. Images stay on the Windows default viewer, which
keeps native previews. If you want IrfanView, open images with it manually — don't
make it the default. Same caution for any portable viewer.

--- MANUAL: default apps (Win11 UserChoiceLatest can't be scripted) ---
Win11's 2025 "UserChoiceLatest" hash protection makes the FINAL default-app choice
un-scriptable. e.g. Archives -> NanaZip: right-click a .zip/.7z/.rar -> Open with
-> NanaZip -> "Always use" (NanaZip auto-registers via MSIX, already in the list).

--- Screenshots = native Snipping Tool (ShareX removed 2026-09-17) ---
Win+Shift+S (native) and PrtSc both open the snip overlay. Nothing autostarts,
nothing to configure, no AHK binding.
Reinstall on a fresh box (the old setup had UNINSTALLED it):
  winget install --id 9MZ95KL8MR0L --source msstore
Registry (now in windows-tweaks.reg): PrintScreenKeyForSnippingEnabled=1 and
PrintScreenKeyForSnippingTool=1 put PrtSc back on the snip overlay. The old setup
set Enabled=0 to free PrtSc for ShareX -- do NOT re-add that.
Do NOT bind #+s in quake-hotkey.ahk: AHK swallows Win+Shift+S before Windows snip
sees it, which is exactly how ShareX used to win the key.

--- PowerShell modules must live OFF OneDrive ---
Documents is OneDrive-redirected, so the default PS module path
(Documents\PowerShell\Modules) gets sync-LOCKED -> Import-Module fails with
0x80070020 "file in use" (PSFzf hit this). FIX (already in the profile): it
prepends $env:LOCALAPPDATA\PowerShell\Modules to $env:PSModulePath. On a fresh
machine, install user modules THERE, not the default:
  Save-Module PSFzf -Path "$env:LOCALAPPDATA\PowerShell\Modules"
(Also: moving files INTO/OUT of OneDrive hydrates them = a one-time download.
 That is the move reading cloud files, NOT the find.exe issue, which stays fixed.)

--- Alt-remaps (mac-style) + AMD dependency (REQUIRED bootstrap step on AMD) ---
quake-hotkey.ahk remaps Alt+C/X/V/A -> Ctrl (copy/cut/paste/select-all) and Alt+Z -> Ctrl+Z (undo),
mac-style (Alt sits where Cmd is). Scoped OUT of WezTerm + RustDesk (they need raw Ctrl). Per-app
shortcuts (Zen, Obsidian) live in each app's own config or a #HotIf WinActive block.
** ON ANY AMD MACHINE: turn OFF all AMD Radeon Software hotkeys ** (Radeon Software -> Settings ->
Hotkeys). Radeon grabs Alt+Z (overlay), Alt+R, Ctrl+Shift+U etc. GLOBALLY, BEFORE AHK sees them ->
the remaps silently fail and the Radeon panel flashes. With them off: Alt+Z=undo, Zen's Alt+R=reload
all work, Ctrl+Shift+U is freed. (Win+W = focus Zen browser / launch if not running, via this AHK.)

--- Open-Shell mechanism (confirmed via source) ---
Live settings = registry HKCU\Software\OpenShell (auto-applied by openshell-settings.reg).
The .xml is Open-Shell's native Backup export (Settings > Backup > Load from XML).
OPEN IT via: (a) click the start button, or (b) Raycast "Classic Start Menu" command
(scripts/raycast/classic-start-menu.ps1). The script posts Open-Shell's IPC message
"OpenShellMenu.StartMenuMsg" (MSG_OPEN=2) to Shell_TrayWnd, then force-focuses the
menu window (OpenShell.CMenuContainer) via AttachThreadInput -> arrows/Enter work
AND Esc/click-away close it (Open-Shell closes on WM_ACTIVATE/WA_INACTIVE).
NOTE: Open-Shell IGNORES injected keystrokes (LLKHF_INJECTED), so simulating keys
(keybd_event/AHK) does NOT work — the IPC message is the ONLY programmatic path.
Key triggers WinKey/ShiftWin = "Nothing" ON PURPOSE: Shift+Win would clash with
Win+Shift+S (Snipping Tool). ShiftClick=WindowsMenu (Shift+click start = Win11 menu).

--- GMEdit + Constructor (GameMaker editor, manual install — not in scoop/winget) ---
GMEdit = a fast GML code editor (alt to the GameMaker IDE). Constructor = a plugin
that compiles/runs GM projects from GMEdit via Igor (needs your GameMaker runtime).
Reproduce on a fresh machine:
  1. Download GMEdit beta (windows zip) from github.com/YellowAfterlife/GMEdit releases
  2. Extract to %LOCALAPPDATA%\Programs\GMEdit ; make a Start Menu shortcut to GMEdit.exe
  3. git clone https://github.com/thennothinghappened/GMEdit-Constructor `
       "%APPDATA%\AceGM\GMEdit\plugins\GMEdit-Constructor"
  4. In GMEdit: Constructor Control Panel (Ctrl+`) -> point at your GameMaker runtime.
Constructor keys: F5 run, Ctrl+` panel, Ctrl+F7 clean, F6 stop, Ctrl+F5 package.
(If the BETA build doesn't see the plugin, it may use a different appdata folder than
 AceGM\GMEdit — check where GMEdit creates its config on first run and move it there.)

--- OBSIDIAN ---
Open Obsidian ANY WAY YOU LIKE (taskbar, Start menu, obsidian:// link). There is no launcher
script any more and nothing special to remember.

THE ARCHITECTURE. Obsidian on this machine opens ONLY the replica at D:\obsidian\sb. It never
touches D:\iCloudDrive\iCloud~md~obsidian\sb. iCloud for Windows serves every file through the
cloud-filter driver, which Obsidian handles badly (dehydrated placeholders read as empty/renamed
notes and it happily writes that damage back up). So Windows edits a normal local folder and a
python daemon -- gursimar/obsidian-icloud-windows-sync, cloned to D:\REPOS by
run_onchange_after_install-obsidian-sync.ps1 -- three-way syncs local <-> iCloud <-> history.
The iCloud vault stays the Mac/iPhone source of truth and is never edited by this machine.
The shell functions follow the same split: `sb` = the replica you edit, `sbi` = look, don't touch.

WHAT STARTS IT. obsidian-sync.lnk in the Startup folder (written by
run_onchange_after_startup-shortcuts.ps1) runs .config/scripts/obsidian/start-sync-daemon.ps1 at
logon. It no-ops if the daemon is already up, so it is also the by-hand way to start it.
This used to live inside the Raycast "Obsidian" command, which meant sync only ran if the vault
was opened THAT ONE WAY -- and when it silently died it stayed dead for five weeks and 54 notes
piled up in iCloud that Windows never saw. Sync is a machine service, not a launcher side effect.

IS IT ALIVE? D:\obsidian\logs\daemon-status.txt holds the last start result; the sync logs sit
beside it. Config is ~/.config/obsidian/sync-config.yaml (chezmoi-managed, NOT the my-config.yaml
in the tool's checkout -- upstream's README tells you to put it there and a git pull eats it).
Known upstream landmines are documented in that file's comments: check_icloud_status MUST stay
false on iCloud 15.9, and .obsidian/plugins/* must stay ignored or the daemon self-loops.
PLUGINS DO NOT SYNC as a result -- install them per-device.
